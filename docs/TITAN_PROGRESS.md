- Universal Supplier Price-List Import — **planned / required for TITAN V1.0; NOT started, no code written; must not begin while the Xero Complete Historical Sync phase is active**. An authorised user hands TITAN a supplier price list in **almost any reasonable format** and gets back a **structured, reviewable supplier catalogue with no manual retyping** of codes, descriptions or prices — the user supplies the file and reviews the result rather than reformatting a spreadsheet into a template, and no supplier is ever asked to change their layout. Input channels are XLSX, XLS, CSV, PDF, DOCX, email body, email attachments, direct paste, images/scans via OCR, supplier quotations and invoices carrying product pricing, each claimed as supported **only after being proven on a real supplier file** and each reporting its own honest status; **perfect extraction is explicitly not promised**, low confidence forces human review, the original file is stored immutably beside the extracted result, and provenance (file, hash, sheet, page, row) plus per-field confidence is recorded on every line. A **12-step workflow** runs receive → register and store with a content hash → identify the supplier (asked, never silently auto-created) → detect format by content → extract with raw payload retained → map columns → clean and normalise → match → classify → human review → **approval** → publish a new immutable supplier price-list version, which then feeds Quotes, Inventory, Purchasing, Job Costing and Finance — **existing quotes are never repriced**, job costs resolve against the version that applied at the time, and import never creates a purchase order, writes to the ledger or touches Xero. **No price becomes active without approval**; a future Owner-configured trusted-supplier policy is off by default and does not exist in V1.0. Column mapping is fully flexible with **no hard-coded layout** — AURA suggests a mapping with per-column confidence, the user confirms, the profile is **remembered per supplier** (several profiles per supplier allowed), a changed layout is detected and re-confirmed instead of silently mapping the wrong columns, unmapped columns are retained, and repeated headers, subtotals, section headings and page footers are excluded with reasons rather than counted as products. Cleaning is explicit and reversible — ZAR formats, decimal comma vs point, thousands separators, parenthesised negatives, VAT inclusive/exclusive/zero-rated/exempt (`unknown` plus mandatory review where it cannot be established, **never an assumed rate**), canonical units with unrecognised values kept verbatim, pack-size parsing without dividing on an uncertain quantity, code and description normalisation that preserves the original, SA `DD/MM/YYYY` dates with ambiguous ones flagged, and discounts only applied on an unambiguous basis; every value keeps raw + cleaned + transformation + confidence and **an uncertain value is never silently changed**, with "POA"/"on request" resolving to `unavailable` rather than `R0`. Each line gets exactly one classification — **new, unchanged, price changed, possible duplicate/replacement, discontinued, needs review, invalid** — where **nothing uncertain auto-merges**, a possible duplicate reaches the review queue with its candidate shown side by side, an item merely absent from a new list is **never auto-deactivated**, invalid lines are excluded with a stored reason instead of dropped, matching is deterministic and idempotent within one supplier and one company, and **line counts must reconcile with zero silent skips**. Price history is **immutable and append-only** via the `previousVersionId` chain with approver and source file recorded, so any past price stays recoverable; AURA reports price movement, largest increases/decreases, supplier cost comparison, margin erosion, stale costs and implausible jumps from real versions only — `unavailable` where history is thin — and **never auto-changes customer selling prices**.
