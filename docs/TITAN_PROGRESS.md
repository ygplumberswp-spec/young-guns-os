## Notes

- Readable vehicle addresses on Cartrack surfaces — **implemented on this branch**. Wherever TITAN shows a vehicle's Cartrack position it now also shows a human-readable address reverse-geocoded from the latest stored `gps_positions` coordinate, in the preferred **street number + street, suburb, city** form. The coordinate remains the source of truth and every surface states how far it can be trusted: a precise fresh match is shown plainly, an area match reads **"Near …"**, a position older than `FLEET_POSITION_STALE_MS` reads **"Last known address: …"** and is never described as live, and a failed or unavailable lookup falls back to the **coordinates plus the real reason** (Google Maps not connected, Geocoding disabled, zero results, provider error) rather than a blank or a guess. Precision comes from Google's own `geometry.location_type` tightened by requiring a street number, so an area centroid can never read as a property address. One resolution layer serves every surface (`packages/shared/src/vehicle-position-address.ts` for the honesty and formatting rules, `apps/api/src/services/vehicle-position-address.service.ts` for provider calls), attached once in `IntegrationsService.buildFleetTrackingContext` so Dispatch, the Fleet dispatch board, vehicle detail, job property maps, mobile and AURA fleet context all read the same decision. Addresses are cached per company on a ~11 m grid for 1 hour, reused while a vehicle stays within 40 m of an already-resolved spot, deduped across concurrent and in-batch lookups, negatively cached for 5 minutes on failure and capped at 10 provider calls per batch — so a dispatch board polling every 3 seconds does not re-geocode, and deferred lookups say so. **No new table and no migration**: no position or address data is duplicated in the database. Navigate uses the existing `buildGoogleMapsNavigateUrl` deep link from real coordinates only, with the moving / movement-unknown / stale warning shown before the tap; Share opens the user's own WhatsApp, SMS or clipboard with the plate, destination, coordinate, position age and directions link and nothing else — TITAN does not send the message and never claims delivery. RBAC is unchanged: the address is only rendered where the caller may already read the Cartrack tracking context (Owner, integrations readers, Dispatch), technicians see their **own assigned vehicle only**, and Client portal and Marketing are denied. - Universal Supplier Price-List Import — **planned / required for TITAN V1.0; NOT started, no code written; must not begin while the Xero Complete Historical Sync phase is active**. An authorised user hands TITAN a supplier price list in **almost any reasonable format** and gets back a **structured, reviewable supplier catalogue with no manual retyping** of codes, descriptions or prices — the user supplies the file and reviews the result rather than reformatting a spreadsheet into a template, and no supplier is ever asked to change their layout. Input channels are XLSX, XLS, CSV, PDF, DOCX, email body, email attachments, direct paste, images/scans via OCR, supplier quotations and invoices carrying product pricing, each claimed as supported **only after being proven on a real supplier file** and each reporting its own honest status; **perfect extraction is explicitly not promised**, low confidence forces human review, the original file is stored immutably beside the extracted result, and provenance (file, hash, sheet, page, row) plus per-field confidence is recorded on every line. A **12-step workflow** runs receive → register and store with a content hash → identify the supplier (asked, never silently auto-created) → detect format by content → extract with raw payload retained → map columns → clean and normalise → match → classify → human review → **approval** → publish a new immutable supplier price-list version, which then feeds Quotes, Inventory, Purchasing, Job Costing and Finance — **existing quotes are never repriced**, job costs resolve against the version that applied at the time, and import never creates a purchase order, writes to the ledger or touches Xero. **No price becomes active without approval**; a future Owner-configured trusted-supplier policy is off by default and does not exist in V1.0. Column mapping is fully flexible with **no hard-coded layout** — AURA suggests a mapping with per-column confidence, the user confirms, the profile is **remembered per supplier** (several profiles per supplier allowed), a changed layout is detected and re-confirmed instead of silently mapping the wrong columns, unmapped columns are retained, and repeated headers, subtotals, section headings and page footers are excluded with reasons rather than counted as products. Cleaning is explicit and reversible — ZAR formats, decimal comma vs point, thousands separators, parenthesised negatives, VAT inclusive/exclusive/zero-rated/exempt (`unknown` plus mandatory review where it cannot be established, **never an assumed rate**), canonical units with unrecognised values kept verbatim, pack-size parsing without dividing on an uncertain quantity, code and description normalisation that preserves the original, SA `DD/MM/YYYY` dates with ambiguous ones flagged, and discounts only applied on an unambiguous basis; every value keeps raw + cleaned + transformation + confidence and **an uncertain value is never silently changed**, with "POA"/"on request" resolving to `unavailable` rather than `R0`.
